🚨 Diagnosis: Why OCR Is Failing on Your Drawing
Problem 1: Text is TOO SMALL in the PDF
Look at your full diagram — it's a huge A1 sheet with hundreds of tiny instrument tags. At 300 DPI, each character in a tag like =H01GDK01 is only about 6–8 pixels tall. EasyOCR needs at least 10–12 pixels to reliably read a character. That's why:

OCR read	Actual
HOT	H01 (only 3px tall → O/0 confusion)
CO	GO (tiny letters)
DNSO	DN50 (S/5, O/0)
GDKO	GDK01 (missed the trailing 1)
XLOS	XL05 (5 read as S)
QMo15-QMO1	QM015-QM01
Every single error is a character confusion that happens at low resolution.

Problem 2: Multiple bubbles look identical
Your drawing has dozens of instruments, each with:

A function (GO, YS, YC, LIC, LS, ...)

A tag (BG004-BG01, BP002-BP01, ...)

A system code (=H01GDK01, =Z04QFB10WP014-WP01, ...)

EasyOCR reads each fragment separately and the grouping algorithm can't reliably associate them because positions are noisy.

Problem 3: PDF probably has a vector text layer
Look at your results — many values like =H01GDK01WP002-WP01, =Z04QFB10WP014-WP0I, =H01GDK01CM002-CM01 are read perfectly or with 1-character errors. That's a strong sign the PDF has real text in it that we should extract directly, not OCR.

If we use PyMuPDF's text extraction, we get 100% accurate text with exact coordinates. No OCR needed. No character confusion.
